# R117: SELECTIVE FACTORY INTAKE + AUDIO FOUNDATION + REVIEW CLOSURE BUILD

Sole live brief. Unattended. Review lane. Maximum useful effort. Long-running autonomous builder
session.

## THE FENCE

- No kit packaging.
- output/ read-only except where this brief explicitly requires asset intake and implementation.
- Do not weaken asset guards.
- Do not disturb the committed banner pair unless a measured, safe improvement is proven.
- Do not bulk-intake the factory.
- Do not commit weak, generic, homeless, or budget-breaking art.
- Do not introduce project-wide WebP unless already clearly supported infrastructure or explicitly
  isolated as a reversible residual with evidence.
- Prefer reversible, additive, locale-safe changes.
- If blocked, record exact evidence and continue. Do not stop early.

## PRECONDITIONS

- On main, up to date.
- Confirm R116 audit findings are available.
- Confirm factory exists: `.scratch/art-review/chatgpt-multi-hour-review-factory/`
- Confirm current live systems: crossed-arms hero idle, hero win/feature reactions, win-tier
  presentation, Overdrive perimeter if present.
- Confirm current dist budget headroom.
- Confirm current sound service and cue map can be inspected.

## GOAL

Use a long builder session to improve the two remaining review-critical axes:

- animation quality via selective proven hero upgrades
- sound design via real cue mapping, fixes, and implementation foundation

Also absorb only the highest-value READY factory assets under strict budget and quality gates.
This is not a bulk import session. This is a selective production session.

# WORKSTREAM 0 - SESSION CONTROL PLANE

### 0.1 Establish baselines

Record before any change: dist size / headroom; current hero reaction set and strengths; current
win-tier presentation state; current feature presentation state; current sound cue inventory;
current dirty placeholder count; current known residuals from R114-R116.

### 0.2 Success criteria for this session

Define and pursue: visible hero animation improvement without regression; measurable audio coverage
improvement; zero locale-breaking art; zero budget overflow; no placeholder sweeps; clear morning
summary of what changed review risk.

---

# WORKSTREAM 1 - FACTORY INTAKE POLICY ENFORCEMENT

### 1.1 Load the R116 classification

Use the audit as the gate, not filenames. Only candidates from READY / high-value hero queue may be
considered.

Hard exclusions: sheet-only assets; blank fade endpoints with massive RGB-under-zero-alpha payloads;
weaker-than-incumbent reactions; homeless systems with no consumer; generic filler that does not
beat live art.

### 1.2 Mandatory intake sanitation

For any accepted raster: zero RGB where alpha is 0; preserve true subject alpha; verify dimensions;
verify no baked text / amounts / letter-x; compare against incumbent when one exists.

### 1.3 Budget gate

Before each intake cluster: estimate cost; estimate residual headroom; refuse the cluster if it
endangers the budget for higher-priority work.

If compression strategy is needed, evaluate carefully and document. Do not silently invent a new
media pipeline.

---

# WORKSTREAM 2 - HERO REACTION UPGRADE PASS

This is the top animation workstream.

### 2.1 Candidate set

Evaluate first-hand, not by audit summary alone. Priority order from R116:
feature-trigger-reaction; power-surge-settle; epic-win-reaction; glance-to-reels; approval-nod; any
stronger max-win reaction only if the hero remains meaningfully visible during max presentation.

### 2.2 Acceptance tests

For each candidate strip, measure: identity vs live rest master; rest return; opaque ground
stability; motion strength vs current live equivalent; visibility under/around the win banner;
whether chest/body readability compensates for head occlusion; loop/enter/exit cleanliness;
performance cost.

### 2.3 Implementation rules

Replace only on clear improvement. Add new states only where they create distinct review-visible
behaviour. Preserve reduced motion. Preserve recovery to idle/rest. Do not regress the current
breathe idle.

### 2.4 Behaviour matrix to implement if art passes

| Game state | Hero behaviour |
|---|---|
| idle / dead spin | current idle or better idle if proven |
| small win | no reaction or tiny approval only if strong |
| meaningful win | win reaction |
| epic-class win | stronger epic reaction if available |
| feature trigger / Overdrive entry | feature-trigger or power-surge response |
| feature active | optional ambient life only if restrained |
| max win | only if visible and not pointless under modal |

### 2.5 Banner occlusion handling

Re-measure occlusion with any newly accepted reactions. Safe options only: leave known composition
limit if body motion still reads; minor reaction-only offset if proven safe; prefer reactions whose
readable mass sits below the banner band. Do not destroy win-amount legibility.

# WORKSTREAM 5 - ANTICIPATION / SYMBOL LIFE DECISION GATE

### 5.1 Architecture check

R116 found large anticipation and symbol-state libraries with no consumer. Do not build a giant new
animation architecture unless a minimal isolated improvement is clearly high-value and low-risk.

### 5.2 Minimal viable animation improvements only

Acceptable: one final-reel anticipation accent if insertion is tiny and safe; one generic land/win
pulse improvement if current symbol pipeline can absorb it.

Unacceptable: full per-symbol state machine from scratch in this session; half-wired systems with no
review payoff.

If the architecture cost is too high, document the exact future brief and move on.

---

# WORKSTREAM 6 - AUDIO FOUNDATION AND WIRING

This is the highest non-art priority in the entire session.

### 6.1 Full cue inventory

Map every existing sound path: UI; spin / stop; land; win tiers; max win; feature trigger; feature
entry; feature active; feature end; anticipation; background music; mute / unmute behaviour.

### 6.2 Missing-cue matrix

Build a matrix of: Moment | Current cue | Status | Priority.

Include at minimum: spin start; reel stop; small win; big / mega / epic / max; feature trigger;
Overdrive entry; Overdrive active loop or stinger; feature end; hero reaction accent if useful;
anticipation riser start/stop; mute recovery.

### 6.3 Fix broken behaviour first

Investigate and fix with evidence any remaining logic bugs around: mute/unmute; anticipation stop;
ducked beds not restoring; threshold mismatches between visual tiers and sound tiers.

### 6.4 Implement safe hooks

Where stems exist, wire them correctly. Where stems do not exist: create durable hook points; naming
conventions; expected file locations; a concrete acquisition list for the next daytime session.

### 6.5 Do not fake audio

No silent placeholders presented as finished sound design. No random reuse that makes the game feel
cheaper.

### 6.6 Review impact statement

Explicitly state how much of the "bad sound design" tag this session can actually move versus what
still requires external stems.
