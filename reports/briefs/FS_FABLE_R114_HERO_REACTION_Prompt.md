# WORKSTREAM 1 - FULL PACKAGE AUDIT

Inventory every asset in the reaction/feature package.

For each important file record:

- path
- dimensions
- alpha
- role
- frame count if strip
- returns-to-rest yes/no
- identity match vs current hero
- status:
  - READY
  - WRONG-FAMILY
  - WEAK
  - HOMELESS
  - REVIEW-ONLY

Especially validate:

- win reaction strip
- glance strip
- energy-up strip
- extra idle strip
- registered hero layers
- Overdrive / feature presentation assets
- support accents

Reject any strip that drifts into a second body family, neutral arms-at-sides stance, or unstable
ground line.

---

# WORKSTREAM 2 - IDENTITY GATE

Before wiring anything, prove the candidate strips belong to the current hero family.

Use first-hand checks, not filenames:

- silhouette similarity to current crossed-arms hero
- ground-line stability
- hand/arm attitude consistency
- no alternate proportions mid-strip

Only family-matched strips may ship.

---

# WORKSTREAM 3 - HERO REACTION ARCHITECTURE

Design the smallest robust reaction system on top of the current flipbook hero.

Required behaviours:

1. Idle remains the crossed-arms breathe cycle
2. Win reaction can interrupt/override idle on meaningful wins
3. Feature / Overdrive energy-up can play on feature entry
4. Glance / attention optional if quality is high and not distracting
5. Always recover cleanly to rest/idle

Explicitly solve:

- what wins trigger reaction
- whether low-value wins stay idle
- whether max-win uses a stronger path
- how reduced-motion is handled
- how simultaneous banner celebration and hero reaction coexist

Do not leave the hero playing the same breathe cycle through dead spins and big wins if the
package can support better.

---

# WORKSTREAM 4 - IMPLEMENT WIN REACTION

Intake and wire the best valid win-reaction strip.

Requirements:

- visible from game distance
- premium, not twitchy
- no foot teleport
- no identity break
- clean enter/exit against rest frame
- no console/asset faults

If the strip is strong, prioritise this over all other hero reactions.

---

# WORKSTREAM 5 - IMPLEMENT FEATURE / OVERDRIVE RESPONSE

If valid energy-up / feature assets exist:

- wire a restrained feature-entry hero response
- optionally use feature presentation support art where it has a real consumer
- do not invent a second feature system

If feature presentation art is strong but homeless, intake what is safe and document exact
insertion points for the rest.

---

# WORKSTREAM 6 - OPTIONAL GLANCE / SECOND IDLE

Only if quality is high and not noisy:

- wire glance/attention on a restrained trigger
- or keep as a second idle variant if that is cleaner

Skip rather than ship distraction.

---

# WORKSTREAM 7 - VISUAL QA ACROSS STATES

Verify:

- base idle
- small win
- big / epic / max path if reachable
- feature entry
- reduced motion
- no regression in layout, car relationship, antenna/visor treatments, or performance

Capture enough evidence to show the hero now responds differently across states.

---

# WORKSTREAM 8 - REVIEW IMPACT + RESIDUALS

Answer explicitly:

- what a reviewer now sees in the first 10 seconds of hero life
- what they see on a meaningful win
- whether this materially improves the animation score risk
- what still blocks a stronger hero performance set

Update the outstanding ledger.
