**R124: REVIEW-CRITICAL CLOSURE INTAKE**

Sole live brief. Unattended. Review lane. Long-running builder session. High care.

### THE FENCE
- No kit packaging.
- No bulk factory intake beyond this named package:
  `.scratch/art-review/chatgpt-review-critical-closure/`
- Do not weaken asset guards.
- Do not disturb locked HUD geometry.
- Do not bake values/labels into images.
- Do not sweep placeholders.
- Refuse any asset that fails first-hand measurement.
- Keep reduced-motion safe.
- Prefer replacements over additive sheets where budget is tight.

### PRECONDITIONS
- On main, up to date.
- Confirm the package exists and inventory it first-hand.
- Confirm current live systems: R122 idle weight-shift; R123 compact win unfold + feature brace;
  R119/R120 operator HUD shell; current win-banner / celebration stack.
- Confirm current dist headroom.

### GOAL
Intake only the review-critical assets that survive first-hand gates:
1. v3 wide-contained win unfold
2. simple Features glyph for paytable/guide
3. text-free win-banner support that does not bury HUD
4. optional hero extras only if they clearly beat current states

This session should leave the game visibly closer to publication on **animation + presentation**,
not just add files.

### WORKSTREAM 0 — SESSION CONTROL
Record baselines before changes: dist / headroom; current hero behaviour matrix; current win-banner
stack; current Features icon in paytable/guide; dirty placeholder count.
Define success as: stronger visible win pose than R123; Features icon no longer the ornate mismatch;
banner support that helps without covering controls/hero/values; no severed limbs; no baked text;
no budget overflow.

### WORKSTREAM 1 — PACKAGE CENSUS
Inventory every delivered file. Separate runtime hero frames/sheets, Features icons, banner
bars/blooms/overlays, optional extras, QA-only contact sheets. Do not treat contact sheets as
runtime assets.

### WORKSTREAM 2 — V3 WIN UNFOLD GATE
This is the highest-priority intake. Re-measure every frame first-hand: identity vs live rest;
first == last; ground stability; silhouette change vs rest and vs R123 win; chest-height width
travel; min/max opaque x; **no fully opaque pixel in column 0 or 679**; no flat-cut limb at 2x
inspection; whether the live 206px-class hero box clips the pose; how much of the peak remains
visible under the live win banner.
Accept only if it is edge-safe, a genuine wide unfold, and stronger and more readable than the
compact R123 win strip. If it fails containment or identity, refuse it and keep R123.

### WORKSTREAM 3 — OPTIONAL HERO EXTRAS GATE
Evaluate approval nod / small-win acknowledgement and feature-active ambient loop. Accept only if:
same identity lock; rest return; edge-safe; distinct and useful; not noisier than the current
feature life; not weaker than current idle/win/feature states for the role they claim.
Refuse max-win hero work. The full-screen max panel still covers him.

### WORKSTREAM 4 — FEATURES GLYPH GATE
Evaluate the 64/96/128 exports. Accept if simple, readable at small size, no baked text, better than
the current ornate Features badge in the paytable/guide, and compatible with the operator-standard
shell. Wire into the paytable / interface guide path that actually renders. Do not leave the old
badge in the visible guide if a better glyph passes.

### WORKSTREAM 5 — WIN-BANNER SUPPORT GATE
Evaluate Big / Mega / Epic bars and the overlays/blooms.
Hard refusals: baked words; baked amounts; baked multipliers; full-stage surrounds that bury Spin /
Bet / hero / live values; assets that fail value-safe centre checks.
Accept only assets that can sit around or behind the current live banner text. If a bar/overlay
helps one tier and harms another, take only the helpful ones. Preserve locale-safe live text.

### WORKSTREAM 6 — BUDGET AND SANITATION
Before shipping any accepted raster: estimate cost; sanitise RGB-under-zero-alpha; keep headroom
safe; replace old sheets where possible rather than stacking more.
If budget is tight, priority order is: 1. v3 win unfold; 2. Features glyph; 3. one best
banner-support winner; 4. optional hero extras last.

### WORKSTREAM 7 — IMPLEMENTATION
Wire accepted assets only.
Hero: keep R122 idle unless a proven better idle appears, which it should not in this package;
replace R123 win strip only if v3 beats it on readability + containment; keep R123 feature brace
unless an extra is clearly better and still restrained.
UI: replace the paytable Features badge if the new glyph passes.
Presentation: add only banner-support layers that survive the HUD-collision test.
Fix any one-line clip/overflow issue if the accepted unfold is clipped by the live hero box.

### WORKSTREAM 8 — FULL QA MATRIX
Prove with evidence: idle; small win; meaningful win / epic-class win; feature entry; feature
active; paytable open; reduced motion; desktop and one narrower width if practical; 60fps / no
console/asset faults; final dist / headroom.
Capture the actual unfold peak, not only the first hop.

### WORKSTREAM 9 — REVIEW IMPACT REPORT
Answer explicitly against the original tags.
**Poor animations:** what a reviewer now sees in 10 seconds; what they see on a win; what they see on
feature entry; whether pose change is obvious at game distance.
**Low quality assets / presentation:** whether Features/paytable mismatch is gone; whether banner
support helped or was refused; any remaining presentation holes.
**Still open:** audio stems; max-win overlay covering the hero; any refused assets and why.

### CLOSE
- Continue through all workstreams
- Measurement-first
- No filler intake
- Guards remain active
- PR on review lane
- Stop when the accepted subset is live and the refused subset is documented with exact evidence
