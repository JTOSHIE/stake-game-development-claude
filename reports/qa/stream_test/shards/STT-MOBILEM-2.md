## STT-MOBILEM-2-01 HIGH Four of the six visible paytable symbol cards are titled with internal tier codes, and the codes reach the reels

- Frames: `/Users/jt/math-sdk/.evidence-scratch/stream-test-upscaled-1600/281_mobile-m_paytable_02_ways_to_win.png`, `/Users/jt/math-sdk/.evidence-scratch/stream-test-upscaled-1600/282_mobile-m_paytable_03_symbol_payouts.png`, `/Users/jt/math-sdk/.evidence-scratch/stream-test-upscaled-1600/289_mobile-m_transition_paytable_closing.png`
- Claim: the SYMBOL PAYOUTS grid titles its cards `WILD`, `SCAT`, `H1`, `H2`, `M1`, `M2`. Two of the six are words a player can read. The other four are the maths package's internal tier codes, printed unaltered as the symbol's public name, in the same weight, size and tracking as `WILD`. Frame `282` shows `H1` and `H2` side by side above their payout columns with `M1` and `M2` entering the view beneath them. Frame `289` shows the same vocabulary reaching the main game surface: the win detail strip under the reels reads `M3  x5  8 ways  $16.00`.
  The source is a hardcoded array, not a naming layer, so every symbol below the two named ones ships its code: `frontend/src/lib/components/PaytableModal.svelte:72-80` declares `` const SYMBOLS = [ { name: 'WILD', ... }, { name: 'SCAT', ... }, { name: 'H1', ... }, { name: 'H2', ... }, { name: 'M1', ... }, { name: 'M2', ... }, { name: 'M3', ... }, { name: 'L1', ... } ]``, and the `name` field is rendered directly as the card title. Nothing in that array routes through the i18n layer.
  This is the standing mandate's named machine-tell, a placeholder string that survived, and neither superseded shard covers it. `STT-MOBILEM-A-02` is scoped to the scatter term and argues `SCAT` reads as a truncation; it does not mention `H1`, `H2`, `M1` or `M2`, though it cites `PaytableModal.svelte:74`, the line directly above them. `STT-MOBILEM-B-09` quotes `M3` and `L2` but files them as the upper-case half of a casing mix on the win strip, not as codes. `STT-MOBILEM-B`'s signed absence reads *"Placeholder strings: none. No `lorem`, `TODO`, `undefined`, `NaN`, `null` or unresolved `{token}` on any frame"*, and that pattern set cannot catch a code that is a well-formed two-character string.
  Stated precisely, because it is the difference between a finding and a preference: a paytable that shows symbol art with no name at all is ordinary and fine. A paytable that gives two symbols English names and six symbols engineering identifiers is not a design, it is an unfinished one, and a rival studio's art director reading `H1` beside `WILD` learns which layer of the build ran out of time.
- Resolution note: NEW AT 1600PX. At roughly 334 image tokens the card titles are legible as the presence of text, but `H1` against a two-glyph word is not separable, and the win strip on frame `289` is far below that.
- Where fixable: `frontend/src/lib/components/PaytableModal.svelte:72-80` for the card titles (not locked); `frontend/src/lib/components/WinBreakdown.svelte:93` renders the same code on the win strip via `` <span class="wb-count">x{current.kind}</span> `` and its sibling (not locked).
- Proposed fix: add a display name per symbol in the string layer and render that instead of `name`, keeping `H1`/`M1`/`M3` as internal keys for the art file lookup at the same site. If naming eight symbols is an art call the owner wants to make, the interim is to render no title for the coded six rather than the code, which is strictly the smaller change.

## Retracted at step 3, recorded rather than deleted

- **RETRACTED: "`base bet` is set in a heavier weight than the figure it qualifies".** Written into the step 2 shard from frames `293` and `294`, where the second line of the MAX WIN cell reads distinctly bolder than the first. **The source refutes it.** `frontend/src/lib/components/BuyBonus.svelte:135` puts the whole string in a single span, and `:240` is one rule for it, `` .buy-stat-val { color: #cfe9ff; font-weight: 700; font-size: 0.92rem; font-variant-numeric: tabular-nums; } ``. There is no second class and no nested span, so `5,000×` and `base bet` are the same weight and the same size. The apparent step is optical: tabular lining figures with open counters against dense lowercase letters at the same 700 weight. The wrap half of that finding is real and stands as STT-MOBILEM-2-05; the weight half is withdrawn.
- **CHECKED AND NOT FILED: the same figure set with and without `.fs-num` on two surfaces.** The paytable renders the max win as `` class="fs-mode-stat-value fs-num" `` (`PaytableModal.svelte:338`) while the dialog's `.buy-stat-val` carries no `fs-num`, which looked like two numeral treatments for one figure. It is not: `.fs-num` is `` font-variant-numeric: tabular-nums; -webkit-font-smoothing: antialiased; text-rendering: geometricPrecision `` (`PaytableModal.svelte:541`, and identically at `WinBanner.svelte:379`, `WinBreakdown.svelte:142`, `MaxWinCelebration.svelte:239`, `FeatureMenu.svelte:609`), and `.buy-stat-val:240` already sets `tabular-nums` directly. The numeral behaviour matches. No finding.
