## STC-LAPTOP-B-12 HIGH (second pass) The FEATURES menu's bet stepper does not bracket the value it steps: `margin-left: auto` on the value strands the `-` button beside an unrelated label

- Frames: `/Users/jt/math-sdk/reports/screens/stream-test-2026-07-28/085_laptop_features_menu.png`, `/Users/jt/math-sdk/reports/screens/stream-test-2026-07-28/084_laptop_transition_features_menu_opening.png`

A minus, value, plus triplet is about as clear a case of intended symmetry as an interface offers, and this one reads as two unrelated groups: `-` is visually attached to the `BET` label it has nothing to do with, and the value is glued to `+`. On `085` the gap between `-` and the value is many times the gap between the value and `+`.
  The cause is one declaration and it is exact. The markup is in the intended order, `FeatureMenu.svelte:341` (`<button class="fm-step" on:click={decreaseBet} ...>-</button>`), `:342` (`<span class="fm-betval fs-num" ...>{price(1)}</span>`), `:343` (the `+` button). The row is a flex row, `:847` (`.fm-betbar > .fs-face { flex-direction: row; align-items: center; gap: 0.7rem; ... }`), with a uniform `0.7rem` gap that would set the triplet correctly on its own. But `:861-862` gives `.fm-betval { margin-left: auto; min-width: 84px; text-align: right; }`, and in a flex row `margin-left: auto` absorbs **all** the row's free space immediately before the value. The gap therefore opens between the `-` button and the value rather than before the stepper, and the `+`, which follows the value in document order, is carried to the right edge with it. The declaration was almost certainly written to push the readout right; the side effect is that it cut the stepper in half.
- Where fixable: `frontend/src/lib/components/FeatureMenu.svelte:861-862` with the markup at `:341-343` (not locked)
- Proposed fix: move `margin-left: auto` off `.fm-betval` and onto `.fm-betlabel` (`:853`), or wrap `-`, the value and `+` in one element carrying it. Either way the free space falls before the triplet, the three travel together with the row's own `0.7rem` gap on both sides of the value, and the readout still sits right. One line moved, no markup change.
