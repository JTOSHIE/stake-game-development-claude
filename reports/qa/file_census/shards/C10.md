## NOTES

**The bundle figure is the real finding, and it is one mechanism with five faces.**
C10-01 through C10-05 are not five independent contradictions; they are five committed
statements about one generated file, and the file has moved under all of them. The
sequence is recoverable from `git log` on the artefact alone: it was committed at
`856fd17` holding 107 files / 15,514,619 bytes, recommitted at `7dd83e6` holding
108 / 15,515,001 with a build stamp naming `856fd17`, and recommitted again at
`ea334fd` (a docs commit, "session report and archive copy") holding 108 / 15,515,148
with a build stamp naming `a1ff78b` and `"cleanTree": false`. Its filesystem mtime is
14:05 while its own `builtAt` is `2026-07-26T03:17:28.609Z`, which is the shape of a
later local re-run rather than a fresh measurement. The dossier's 15,515,125 and its
operand 15,514,744 appear in NONE of the three versions. I checked for the obvious
innocent explanation, that the dossier cites a different file: it does not, it names
`reports/qa/dist_hygiene_2026-07-26.json` explicitly, and there is exactly one
`dist_hygiene_*.json` under `reports/qa/` (`ls reports/qa/dist_hygiene*.json` returns
one path). So the submission-facing figure is 381 bytes of arithmetic that its own cited
evidence cannot reproduce. The working-tree copy is identical to HEAD
(`git diff --stat` on it is empty), so this is committed state and not local dirt. I did
not run the gate to find the true figure: this is a read-only pass, and a rebuild is the
only thing that could answer it.

**I nearly filed a wrong second half of that finding, and the refutation is C10-15.**
The obvious next claim was that the gate still points at the committed path, so any local
re-run keeps dirtying it. `dist_hygiene_gate.mjs:40` reads
`const QA = evidenceDir('reports', 'qa')`, which looks exactly like a committed path. It
is not: `evidencePaths.mjs:51` resolves it to a gitignored `.evidence-scratch/` tree
unless `FS_WRITE_EVIDENCE=1` is set. So the drift is HISTORICAL, closed by that module,
and the live defect is only the broken citations. Chasing the helper rather than trusting
the constant name is what separated the two, and it also turned up C10-14 in the opposite
direction: convention (h.1) still calls the migration open work when the code shows it
done.

**Why I tiered the bundle rows HIGH and not STREAM.** No player sees a byte count. But
`SUBMISSION_DOSSIER.md` is the document an external reviewer opens first, TR-047's whole
lesson was recorded as "a committed size a reviewer cannot reproduce is worse than none",
and this is that failure recurring one level down: the figure is now cited to an artefact
rather than to a machine, and the artefact disagrees. Convention (l.3) is the test it
fails, not a style rule.

**The locked-path gap, stated carefully, because the loose reading of it is wrong.**
`.claude/settings.json` has no `Edit(...)` or `Write(...)` deny rule protecting itself.
That is a real gap in the tool-level lock and both C10-07 and C10-08 quote it. What it
is NOT is an unguarded path: `scripts/qa/locked_paths_gate.mjs:78-83` carries it in
`LOCKED` and its seeded self-test includes the case (`'.claude/settings.json committed
with no token'` expecting FAIL), so a COMMIT touching it is caught in CI. The defect is
narrower and worth stating precisely: the gate's header comment claims all four paths are
"transcribed from `.claude/settings.json`'s deny rules", and one of them is not in those
rules at all, so a reader who trusts the comment will believe the Edit tool is blocked on
the lock mechanism when it is not. Whether to add the two deny lines is an owner call,
since a deny on the settings file would also block the sanctioned temporary lift that
convention (e) requires, and that tension is exactly why I am recording it rather than
proposing a fix.

**Three assigned targets came back clean and I am recording them as clean.** Mode costs
agree across four files; RTP agrees across four files; the branch list matches the remote
exactly. On the RTP check I deliberately compared at each file's own stated precision
rather than rounding to a common one, because `game_config.py` carries `0.9635` while
`GAME_FACTS.md` carries a 10dp figure per mode, and a naive comparison would have
manufactured a disagreement out of a precision difference. On the branch check I confirmed
`origin/HEAD` is a symbolic ref rather than a seventh branch before calling the count six.

**One scope note on a path in my own brief.** The brief names `docs/GAME_FACTS.md`. There
is no such file; `GAME_FACTS.md` sits at the repository root, and `README.md:34` links it
there (`[\`GAME_FACTS.md\`](GAME_FACTS.md)`), as does `SUBMISSION_DOSSIER.md:765`. I audited
the root file. This is a brief typo, not a repository contradiction, and I record it only
so the marshal does not read my rows as being about a file that does not exist.
