NOTHING NORMATIVE was found in front_end.md (one paragraph of description of what the frontend-sdk is, plus a pointer to technical details), front_end_dependencies.md (a list of the npm dependencies "of this repo", that is the platform's repo, not of a submission), front_end_file_structure.md (the Turborepo apps/ and packages/ layout, package naming convention and workspace imports, all internal to the reference monorepo), front_end_context.md (the four Svelte contexts, xstate game actor states and PIXI app state of the reference implementation), front_end_task_breakdown.md (a methodology recommendation to split large emitter-event handlers, plus definitions of stateless and stateful games), front_end_adding_new_events.md (a step-by-step tutorial for adding a bookEvent to /apps/lines, entirely file-path specific to the reference repo) and front_end_storybook.md (a catalogue of the sample games' Storybook stories; its closing line "If each bookEvent is implemented well with emitterEvents and its story is resolved properly, the game is technically finished." is a claim about the reference workflow's completeness and not an obligation on a submitted build). TWO NEAR-MISSES, both deliberately NOT given rows, with the quotes kept so the judgement is checkable. First, front_end_ui.md:54 is a permission rather than an obligation and is the clause that explicitly releases a submission from this whole tree: "For the branding purpose, we recommend you to regard them as just an example of UI packages instead of applying them directly to your final product. It would be a good choice to use them as a starting point and add more style to them to build your UI. It is completely fine to ignore them and build your own UI from scratch." A recommendation that ends by permitting the opposite places no requirement, and it is evidence that not using the platform's UI packages is sanctioned. Second, front_end_getting_started.md:21 "Install node with version 18.18.0." and :34 "Install pnpm with version 10.5.0." are imperatives, but they are toolchain steps for running the platform's sample games locally, not properties of a shipped artefact, so they bind nobody on this project. I was not bounded: all ten pages were read end to end and the total body is small (about 36k characters across the ten captures).
