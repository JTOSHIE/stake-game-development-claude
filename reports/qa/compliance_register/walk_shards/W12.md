## PER REQUIREMENT NOTES

### REQ-133, fully functional, no non-working feature or dead control

Two halves, and both have something real behind them, which is why this is the only
SATISFIED row in the slice.

The dead-control half has a genuine CI gate. `.github/workflows/checks.yml:194-196` wires
`node scripts/dead_wiring_scan.mjs` into the `static gates` job, and the script exits 1 on
any exported store written by a control and read by nothing (`dead_wiring_scan.mjs:160-166`,
quoted above). The class it guards is the real defect shape recorded in its own header:
"standingMode (2026-07-07) - selecting Cruise or toggling OVERBOOST wrote a store that
handleSpin never read; the spin request was hardcoded to mode: 'base'."

The functional half has committed evidence: `reports/qa/dtt_live_session_2026-07-26.md` is a
transcription of a real published session on the platform, and
`docs/records/compliance/STAKE_GUIDELINES_SELF_ASSESSMENT.md:32` records "The published game
launched, drew a real balance and played 143 live rounds settling against the wallet" against
the platform's own PreChecks item 1.

THREE WEAKNESSES, recorded rather than smoothed over:

1. **The gate has no convention (p) seeded self-test.** There is no
   `dead_wiring_scan.mjs --self-test` step in `checks.yml` (I read the whole file; the wired
   self-tests are locked-paths, dash, machine-tell, asset-reference, the books verifier and
   the browser legs). So the gate's PASS has never been shown to be capable of being a FAIL.
2. **The live-session evidence is dated 2026-07-26 and it is not clean.** Its own status
   line says "four frontend files never reached the portal and one of them is a live
   player-visible asset; the published bundle is one commit behind `main`". That is an
   upload-completeness defect at the artefact the platform actually holds, not a repository
   defect, and I could not establish the current state of the portal from this repository.
   `asset_reference_gate.mjs` (wired at `checks.yml:490-496`) closes the neighbouring class
   inside `dist`, not the class of a file that never got dragged into the portal.
3. `dead_wiring_scan.mjs` is a scan of exported stores, not of controls. A control wired to a
   store that is read but whose handler ignores the value is invisible to it.

**What IS gated, and it is good.** `frontend/src/lib/services/roundInterpreter.ts:1-21` is

  raw[0].slice(1, 5).map((c) => c.name))"
- `:107-108`: "check(`${label}: interpreter total equals the book payoutMultiplier`,
  out.script.totalWinCentibets, round.payoutMultiplier)" under "TOTALS reconcile to the book,
  which is the money-path claim".

Wired at `checks.yml:374-376`: "- name: rgs parse alignment / working-directory: frontend /
run: npx tsx src/lib/services/rgsService.parse.test.ts". Mode costs have their own drift gate
