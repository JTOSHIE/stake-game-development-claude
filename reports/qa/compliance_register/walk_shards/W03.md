## PER REQUIREMENT NOTES

**REQ-070, sound disable.** The control is real and player-reachable: `HudOverlay.svelte` renders the
audio panel in four separate layout branches (`:430`, `:573`, `:657`, `:819`), each with the same
`on:click={toggleMute}` item, and `soundService.ts:169-177` persists the flag
(`isMutedStore.subscribe(val => { setMuted(val); persistMute(val) })`). I opened
`02-hud-menu.png` and the `Mute` item is visibly present, so the evidence is genuine rather than
assumed. **The weakness worth recording: nothing would go red if the control were deleted.** I
searched every file under `frontend/scripts/` for `audio-mute` and `Unmute`; the only hit is
`machine_tell_gate.mjs:594`, and that is a SEEDED self-test fixture body
(`body: "<button>\n  {$isMuted ? 'Unmute' : 'Mute'} ..."`), not an assertion about the shipped
component. `audio_verify.mjs` contains no `mute` string at all. So the proof is a static 2026-07-25
frame, which shows the control existed at capture time and cannot go red on a regression. Also
KNOWN(Q-16 park): the label is hardcoded English (`{$isMuted ? 'Unmute' : 'Mute'}`), which
KNOWN_OPEN.md names explicitly as parked.

**REQ-071, spacebar to bet.** The handler is correct and better than the bare requirement: it
declines in replay mode, in text fields, under `$bettingDisabled`, under `$anyModalOpen`, and under
`$rgJurisdiction.spacebarDisabled`, then `e.preventDefault()` before `if ($canSpin) handleSpin()`.
The proof is committed captured output showing a real `page.keyboard.press('Space')` produced a
spin. **Two caveats.** First, `platform_conformance_item2.mjs` has ZERO occurrences in
`checks.yml`, so this evidence is a local run, not a gate; a regression would be caught only by the
next manual run. Second, the evidence is dated 2026-07-14, older than the modal-guard rework the
handler's own comments describe as R8/TR-016 (2026-07-25) and R2R (2026-07-26), so the captured
run predates the current handler. The wired `responsible gambling enforcement` step
(`checks.yml:305-307`) does defend the jurisdiction half only:
`check('disabledSpacebar derives', j.spacebarDisabled === true)` at
`responsibleGambling.test.ts:174`, with the file's own comment at `:209` conceding the boundary,
"disabledSpacebar is read by App.svelte's key handler. Asserted against the" store, not against the
handler. Nothing asserts that Space still reaches `handleSpin`.

**REQ-072, autoplay explicit confirmation. FINDING.** The implementation satisfies the platform
text as the gate's own reading construes it: there is exactly one `isAutoPlay.set(true)` in the
whole frontend, inside `startAuto`, and `startAuto` is reached only from
`on:click={() => startAuto(n)}` count buttons, so the count tap is the confirmation and no single
click starts a run without one. The defending artefact exists and is well written, including a
liveness check for dead duplicate components. **It is not wired.** I grepped
`.github/workflows/checks.yml` for `check_autoplay_confirm_gate` and got zero. Every other gate of
its class in that file is invoked by name (`node scripts/dash_gate.mjs --self-test`,
`node scripts/machine_tell_gate.mjs --source`, and so on), so this is an omission rather than a
naming convention I misread. It also carries no `--self-test`, so even locally it has never been
seen to fail: by convention (p) it is a script that prints PASS. A second start path (the
keyboard shortcut, URL param or automatic continuation the gate names) could land on main and go
green.

self-test but its subject is whether the turbo BUTTON's three states are visually

present. **Nothing tests it.** I enumerated every reference to `parseReplayParams` in the

defaults to when a replay URL omits currency"), and the second is a comment ABOVE an assertion
about `currency.ts`, not about the parser. `replay_blocker_proof.mjs` is unwired. What I can cite

`reports/screens/replay-blocker/02_base_ready_eur.png`, which I opened, renders `Mode: BASE`,
`Bet: €10.00` and `Currency: EUR` on the replay entry card, so mode, amount and currency were
honoured on that run. That is evidence of one past run, not a defence: `lang` and `social` are not
visible in that frame, and an edit to the parser would go green everywhere. I record the verdict as
NO_PROOF rather than SATISFIED because the strongest available artefact for the requirement as
worded is a screenshot of three of its six parameters.
