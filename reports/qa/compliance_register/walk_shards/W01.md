## PER REQUIREMENT NOTES

### REQ-052 (unique audio and visual assets) — NO_PROOF

The platform text is "Submitted games must use unique audio and visual assets. Assest such as
backgrounds, symbols and/or animations provided with the web-sdk sample games will not be
approved for publication."

What I opened. `design-system/brand/GENERATION_NOTE_background.md` is a real provenance record
for one asset (the scene backdrop) and it is the shape `CLAUDE.md`'s Assets convention asks for:
origin, source hash, shipped hash, dimensions, what the supplier claimed and what the
measurement found. `frontend/src/lib/config/themes.ts:34` shows the shipped theme's assets are
served from our own `assets/themes/future-spinner` tree. `design-system/brand/` also holds
`tile/`, `hero_emblem/`, `hero_icon/`, `provider_mark/`. So the implementation side is real for
the assets that have records.

What I could not establish, and it is the finding. **There is no proof path of any grade.** I
read the whole of `.github/workflows/checks.yml` (671 lines): its 30-odd steps cover locked
paths, types, dead wiring, wallet floats, currency scale, mode-cost drift, locale completeness,
a11y social terms, vocabulary, dashes, machine tells, bet ladder, RG, modal guard, live guard,
session recovery, feature resume, scatter escalation, launch params, RGS parse, wallet contract,
currency, social locale, replay rounds, `npm run check`, the build, asset references, dist
hygiene and the books verifier. None of them has asset ORIGIN as its subject.
`asset_reference_gate.mjs` asserts only that referenced paths exist in `dist`; a web-sdk sample
background would satisfy it perfectly. `dist_hygiene_gate.mjs` asserts documentation is absent.
I also grepped `docs/records/reviews/REVIEW_TRACKER.md` and `docs/QUALITY_CHARTER.md` for
`web-sdk`, `sample game`, `sample-game`, `originality` and `original IP`: the only hits are
TR-088 (`REVIEW_TRACKER.md:263`), which is about the upstream **maths** sample packages under
`games/`, not about frontend art, and `QUALITY_CHARTER.md:480`, the same subject. So this
requirement is neither gated nor parked. Severity HIGH rather than STREAM because nothing is
currently visibly wrong; the exposure is that a reintroduced sample asset would ship silently.

Also worth recording as a proof-design note: an originality gate is not obviously writable as a
pure predicate, since "is this asset ours" is a provenance question rather than a file-content
one. The cheapest honest instrument is probably a committed manifest of shipped asset hashes
with a provenance line each, plus a gate asserting every asset in `dist` appears in it. That is
a proposal, not a finding.

### REQ-053 (free of visual bugs, broken or missing assets or animations) — NOT_MET, KNOWN(C-01)

The platform text is "Ensure the game is free of visual bugs, including broken or missing assets
or animations."

The MISSING-FILE half is genuinely gated, and well. `.github/workflows/checks.yml:490-496` wires
both legs of `asset_reference_gate.mjs`, the seeded self-test first per convention (p):

```
      - name: asset references, seeded-violation self-test
        run: node scripts/asset_reference_gate.mjs --self-test

      - name: asset references resolve in dist
        run: node scripts/asset_reference_gate.mjs
```

and the gate itself fails red on a dangling reference (`asset_reference_gate.mjs:201`,
`` console.error(`ASSET REFERENCE GATE: FAIL, ${missing.length} referenced path(s) are not in dist:`) ``)
with a negative control asserting a real shipped asset is not flagged (line 186).

**But the requirement says "or animations", and the animation half is not met.**
`reports/qa/stream_test/KNOWN_OPEN.md:52` records, as a Session 1 panel-confirmed correction to
two shards that had both cited the wrong cause: "**C-01's real cause is `GameGrid.svelte:499`,
`DROP_H = 520`**, not the CSS both shards cited. The reel window is bare by construction for 312
of 412 pixels on every drop." I opened `GameGrid.svelte:499` and the line is there as recorded
(`const DROP_H = 520`, with `startY = REST_Y - DROP_H` two lines down). A reel window that is
bare for most of every drop is a broken animation state on the single most-watched surface in
the game, so I am marking this NOT_MET rather than NO_PROOF, and reporting it as **KNOWN(C-01)**
rather than opening anything new.

Two further limits of the proof, recorded because they bound what green means here:
`asset_reference_gate.mjs` reads STATIC references, so an asset composed at runtime from a
template string is invisible to it; and no gate in either CI job asserts an animation reaches
its expected visual state, which is exactly the class C-01 sits in.

### REQ-054 (popout / mini-player, undistorted) — SATISFIED

The platform text is "Games must support this small view without the active game board been
visibly distorted."

Implementation. There is a dedicated third layout profile rather than the compact strip squeezed
further, and the comment says why: `HudOverlay.svelte:62-66`, "Stake's 400x225 mini-player popout
gets its OWN layout... 76px of a 225px viewport is a third of the screen before a control is
placed". It is selected in `App.svelte:1023` on both axes, and the board is scaled by
`Math.min(window.innerWidth / FRAME_W, availH / MINI_CROP_H)` (`App.svelte:1058`), a SINGLE
factor applied through `transform: translateX(-50%) scale(${miniCanvasScale})`
(`App.svelte:1789`). One uniform factor on both axes is the property "undistorted" actually
asks for, which is why I am citing the scale computation and not a CSS block.

Proof. `layout_fit_gate.mjs` carries `{ name: 'Popout S', width: 400, height: 225 }` as one of
its seven presets (line 69), and it is a real CI gate: `checks.yml:571-572` is the matrix leg
`"browser: layout fit"` running `node scripts/layout_fit_gate.mjs`, in the `browser` job that
installs chromium. It fails on vertical scroll, horizontal scroll, document scroll, any control
outside the viewport, and any readout clipping its value (lines 225-229).

**Two weaknesses in that proof, both real.** First, convention (p): layout fit and contrast are
the only two of the eleven browser legs invoked WITHOUT `--self-test`. Compare their neighbours,
which all run `node scripts/X.mjs --self-test && node scripts/X.mjs`. I checked the scripts as
well as the workflow rather than assuming the flag was merely omitted from the matrix:
`grep -c "self-test\|selfTest"` returns **0** for both `layout_fit_gate.mjs` and
`contrast_gate.mjs`, so there is no self-test to wire. This gate has therefore never been seen to
go red on a seeded violation, and `checks.yml`'s own header records that four consecutive runs
(117 to 120) had this exact gate crashing at `chromium.launch()` rather than asserting, while its
committed result was being cited. Second, the gate asserts
FIT and REACHABILITY, not aspect ratio: a board stretched non-uniformly would still fit, still
scroll nowhere, and still pass. The undistorted property is defended by the single-factor
`scale()` in the source, not by the gate.

Supplementary evidence, opened: `reports/qa/popout_conformance_2026-07-27.json` records
`"popout-S-400x225"` with `"btnInViewport": true`, `"cardWithinViewport": true`,
`"realClick": true`, `"failures": []`, `"pass": true`; and
`reports/qa/mini_player_proof_2026-07-26.json` records six named states at 400x225 with
per-control geometry and `"truncated": false`. `checks.yml:82-86` states plainly that
`popout_conformance.mjs` is "NOT ADDED HERE ON PURPOSE" and that its result is committed, so
that script is correctly graded SCRIPT_UNWIRED-with-committed-evidence rather than a gate.

Same two caveats as REQ-054: no seeded self-test on this leg, and "reachable" is measured as

### REQ-056 (images and fonts from the Stake Engine CDN only) — SATISFIED

The platform text is "All images and fonts must be loaded from the Stake Engine Content Delivery
Network (CDN)." As the slice notes, the operative meaning is that assets ship inside the uploaded
bundle and are served from it, so the test is that nothing is fetched off-origin.

Implementation. Images: `themes.ts:34`, `assetBase: 'assets/themes/future-spinner'`, a
bundle-relative path with no scheme and no host, consumed as
`src="{$themeAssets.assetBase}/ui/{f}"` (`PaytableModal.svelte:370`). Fonts: `main.ts:2-4`
imports `@fontsource/orbitron` at three weights, so the woff2 files are bundled by Vite rather
than fetched; `app.css:94` records the same intent in a comment, "Orbitron is self-hosted via
@fontsource".

Proof. `reports/qa/build-diet-network-log.json` is a captured request log from the BUILT bundle
and every one of its 52 entries is same-origin `http://localhost:<port>/...`. I checked the
negative direction rather than eyeballing the head of the file: filtering out `localhost` and
then grepping for `url` returns zero lines, so there is no off-origin request in the capture at
all.

What I could not establish, and it is worth recording even though the verdict is SATISFIED.
**No CI step enforces this.** `build_diet_verify.mjs` is not in `checks.yml` (I read the whole
file), so the network log is a dated artefact, not a gate: someone adding
`<link href="https://fonts.googleapis.com/...">` tomorrow would go green through both CI jobs.
`CLAUDE.md`'s Compliance section states the check as a manual pre-commit grep
("must be empty"), which is a convention rather than a machine backstop. And `CLAUDE.md`
convention (p) names `build_diet_verify.mjs` by name as one of the four scripts in this
repository that has printed PASS while broken, so this particular evidence source has a history.
Severity MEDIUM: not player-visible while correct, but an off-origin font is both an approval
failure and a live-availability risk.

inside the fill. Its only presence check is aggregate: `if (!result.cards.length) findings.push('no cards found, so nothing was actually checked')`
(line 330) across all three selectors together, so `.fs-sym-card` alone satisfies it.
**Delete the RTP row and the RTP stat and this gate stays green.** `fsModes.drift.test.ts`
checks costs only, never RTP (grepped: no `RTP` or `rtp` token in it). So no CI gate would go red.

That leaves EVIDENCE as the real grade: `reports/qa/paytable_card_fill_gate_2026-07-27.json`

`reports/screens/rules-conformance-item1/bet-modes-section.png`. Note honestly what evidence
cannot do: a stale screenshot does not become visibly wrong when the figure is removed, so this
protects the past capture rather than the next edit.

One further unproven claim, flagged for the marshal rather than asserted: nothing I found ties

deliberately NOT citing it here, because citing it would close a requirement it does not touch.
