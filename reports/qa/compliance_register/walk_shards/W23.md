## PER REQUIREMENT NOTES

### REQ-132, NO_PROOF, STREAM

**What the platform text actually asks.** Quoted verbatim from
`docs/stake-engine-live/2026-07-29/front_end_flowchart.md:22`: "It resolves them one after
another with sequence() in the order of the bookEvents array. It means the sequence of
bookEvents matters eminently and it determines the behaviors of the game. For example, we
don't want to see the "win" before "spin", so we should put "win" after the "spin"." The
obligation is on the CLIENT: consume the supplied order, resolve each event before starting
the next, and never show a later beat ahead of an earlier one.

**This product does not use the platform's `playBookEvents()` at all.** `grep` for
`bookEvents`, `book_events` and `bookEvent` across `frontend/src`, `frontend/scripts` and
`scripts/qa` returns nothing. There is no `packages/utils-book`, no `bookEventHandlerMap`
and no `sequence()`. The equivalent is a three-part local pipeline, so the requirement was
checked against that pipeline rather than against a missing SDK import.

**The implementation, opened and quoted at each of the three parts.**

1. `frontend/src/lib/services/roundInterpreter.ts:171` walks the raw event list in supplied
   array order and finalises the previous spin the moment a new `reveal` arrives, which is
   the ordering guarantee at derivation time:

   ```
   for (const ev of events) {
     switch (ev.type) {
       case 'reveal': {
         // finalize the previous spin before starting a new reveal
         pushCurrent()
   ```

   Its own header at line 1 states the contract: "pure, typed interpreter that converts one
   book round into an ordered presentation script for the Overdrive Free Spins feature."

2. `frontend/src/App.svelte:1445` awaits the reel animation before any win state is
   published, i.e. the "spin" resolves before the "win" is shown:

   ```
   if (gridRef) await gridRef.animateSpin(result.board)

   boardSymbols.set(result.board)
   activeWins.set(result.winEvents)
   ```

   and `App.svelte:1523-1537` defers the whole settlement past the feature playback, which
   is the same rule at round scale. The comment above it at `App.svelte:1480-1493` names the
   defect class in terms: "For a normal (non-wincap) triggered round, `win` is the ROUND'S
   FULL total (base + every free spin combined) - settling it here, before presentFeature
   plays, would reveal the entire outcome before the free spins have even been shown."

3. `frontend/src/lib/components/FreeSpinsPresentation.svelte:303-348` plays the free spins
   one at a time and only schedules the next when this one has resolved, including awaiting
   the retrigger ladder:

