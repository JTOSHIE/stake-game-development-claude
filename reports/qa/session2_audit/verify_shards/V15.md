and a grep for `0.01`, `0.02` and `0.05` across `frontend/src/lib/stores`, `config` and `utils`
(tests excluded) returns nothing, so no sub-dime level exists and nothing asserts one. The
DIAGNOSIS fails on two legs. First, `betLadder.test.ts:37` does not "assert the OPPOSITE floor as
the expected fallback"; it sits inside the block headed at `:29` "THE SHIPPED DEFECT, reproduced
arithmetically against the hardcoded ladder", and the value it expects is what the old locked
`gameStore.increaseBet` WOULD have returned. It documents a bug. It pins `BET_LEVELS[0] === 0.10`
only as a side effect, so the observation survives while the reading of it does not. Second, the
finding treats the hardcoded array as the ladder a player sees. It is not: `betLadder.ts`'s
`activeBetLevels` prefers `rgsBetLevels`, so the $0.10 floor is only the no-RGS-levels fallback,
and the operative floor in production is the operator's own. On severity, the platform text is a
recommendation twice over, `rgs.md:287` "Although bet levels are not mandatory" and `:295` "should
incorporate", so HIGH overstates a should-clause whose operative value comes from the platform.

a sub-dime fallback ladder, and REQ-125 to REQ-127 (the win-precision half of the same
`rgs.md:295` paragraph) are unimplemented too, so adding levels alone would not satisfy the
paragraph. Those are separate register rows, so this finding is not INCOMPLETE for omitting them,
but see new finding 3.

   maxBet" and `:290` "The bet must be divisible by stepBet", are enforced nowhere client-side. The
   parse side is LOCKED; the consumption side is not, so a non-locked guard is possible.

   `rgs.md:295` is unimplemented. `frontend/src/lib/utils/currency.ts:211`:
   `const decimals = ZERO_DECIMAL.has(code) ? 0 : 2`, overridable only when the platform supplies

   the platform text requires four points of precision at a $0.01 base bet. This is REQ-125 to
   REQ-127 territory rather than REQ-124, so it does not make S2-C062 incomplete, but the concrete
   state is recorded here because I verified it and the sub-dime cluster reads as if the ladder were
