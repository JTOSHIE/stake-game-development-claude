## NEW FINDINGS FOUND WHILE VERIFYING

**NEW-V17-01. `frontend/scripts/bet_selector_gate.mjs:332-333`: the convention (p) seeded
self-test for the off-ladder refusal is self-referential and cannot go red.** The seed is
manufactured by applying the detector's own regex to the source, then the same regex is tested
against the result:

```
332:    const seededLadder = ladderSrc.replace(/if \(!levels\.includes\(level\)\) return false/, 'if (false) return false')
333:    const caughtRefusal = !/if \(!levels\.includes\(level\)\) return false/.test(seededLadder)
```

If the pattern matches, `replace` removes it and `.test` is false, so `caughtRefusal` is true.
If the pattern does NOT match, `replace` is a no-op, `.test` is still false, and `caughtRefusal`
is true again. The assertion at `:344`, `if (!caughtRefusal) problems.push('SEED NOT CAUGHT:
setBetLevel without its off-ladder refusal')`, is therefore unreachable for any realistic
source; only a source containing the pattern twice could trip it, because the regex is not
global. Concretely: reformat the real refusal to `if (!levels.includes(level)) { return false }`
and the gate's own live check at `:322` goes false while this self-test still prints `caught`.
That is exactly the failure convention (p) was written for, "a gate whose self-test seeds a
defect in a form the gate happens to handle, while the real defect occurs in another form, has
learned nothing", and it means W16's assessment that the gate "does carry a convention (p)
seeded self-test ... That is real proof of the CONSTRUCTION argument" is too generous. A real
self-test would run the gate's predicate function over the seeded string, not re-run the seeding
regex.

**NEW-V17-02. `frontend/src/lib/stores/betLadder.ts:105-112` understates its own fallback, and
`:39-41` is where the minStep-by-construction argument actually breaks.** The doc comment says
every offerable value "came out of `activeBetLevels`, which is the authenticate response's own
`betLevels` (or the built-in ladder in mock and dev)". `rgsBetLevels.ts:13-14` is the honest
statement of the same thing: "Empty array means \"no RGS levels available\" (mock/dev mode or
auth failure), in which case consumers fall back to the built-in BET_LEVELS defaults." Auth
failure is not mock and it is not dev. `activeBetLevels` at `betLadder.ts:39-41`,
`$levels.length > 0 ? $levels : BET_LEVELS`, then supplies hardcoded USD-shaped amounts, which
for any non-USD currency are not values the platform authorised. `betLadder.test.ts:88` and
`betSelector.test.ts:97` both set `rgsBetLevels.set([])`, so the fallback is an intended and
pinned path rather than dead code. Recorded as a documentation-versus-behaviour mismatch with a
named live trigger; whether a wager can actually be placed in that state was not established
here and is the question that decides its severity.
