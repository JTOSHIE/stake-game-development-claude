## PER CLUSTER REASONING

### S2-C001, REQ-053, NOT_MET with a partial CI gate

Both halves are true at HEAD and the arithmetic is on the finding's side.

The gate half: `checks.yml:494-496` runs `node scripts/asset_reference_gate.mjs` and `:490-492`
runs it `--self-test` first, so it is genuinely wired AND satisfies convention (p) for the class
it covers. What it covers is stated in its own header: *"asset_reference_gate.mjs: every asset
path the code references exists in dist"* (`frontend/scripts/asset_reference_gate.mjs:3`). An
asset-existence reader cannot see an animation state at all, so calling it partial is right.

The defect half: `GameGrid.svelte:499` is `const DROP_H = 520`, and `startY = REST_Y - DROP_H`
= -104 - 520 = -624. The strip holds 7 slots of `TILE` 104 (`:72,74`), so it spans window-y
-624 to +104 while the window is `CANVAS_H` 412 (`:67`). At the start of every drop only the top
104 px of the reel window carries a tile and 308 px does not, and solving
`-624 + 520f² >= 412 - 728` gives `f >= 0.77`, so the window is not fully covered until 77 per
cent of the 400 ms fall has elapsed. `reelMode` defaults to `'drop'` and `GameGrid.svelte:1054`
says of that branch *"THIS IS THE SHIPPING PATH"*, so this is every spin of the shipping build.

**My hostile attack, and why it failed.** I tried to refute the requirement mapping: REQ-053 as
the register paraphrases it is about *"broken or missing textures, sprites, fonts or animation
states"*, and a reel that is briefly empty is a motion-design defect rather than a missing asset,
which would make REQ-050 the right row and this disposition an overstatement. The verbatim source
kills that argument. `approval_guidelines_front_end_communication.md:23` reads *"Ensure the game
is free of visual bugs, including broken or missing assets or animations."* The leading clause is
general, so the bare window is in scope and NOT_MET stands.

Two things to carry forward rather than treat as refutations. First, this is **not new**:
`reports/qa/stream_test/KNOWN_OPEN.md:50-51` already records *"C-01's real cause is
`GameGrid.svelte:499`, `DROP_H = 520`"* and the 312-of-412 figure, confirmed by a Session 1 panel.
Severity order HIGH is right; novelty is nil. Second, question 5 on the register itself:
`REGISTER.md:123` paraphrases that source line as a list of asset classes and **drops the broader
"free of visual bugs" clause**, which is the narrowing that made my attack look viable for a
minute. The row understates its own requirement.

## NEW FINDINGS FOUND WHILE VERIFYING

**NEW-1. Replay does not normalise a trailing slash on `rgs_url`, and the live client does.**
`frontend/src/lib/services/replayService.ts:73-75`:

```ts
  const rgsUrl = rgsUrlRaw.startsWith('http')
    ? rgsUrlRaw
    : `https://${rgsUrlRaw}`
```

then `:125` builds `` `${p.rgsUrl}/bet/replay/${p.game}/${p.version}/${p.mode}/${p.event}` ``. A
launch carrying `rgs_url=rgs.stake-engine.com/` therefore produces
`https://rgs.stake-engine.com//bet/replay/...`, a double slash. The live path handles exactly this
and is tested for it: `frontend/src/lib/services/rgsService.contract.test.ts:68` asserts
`check('a trailing slash is trimmed so paths do not double up', normaliseRgsUrl('rgs.example.com/'), 'https://rgs.example.com')`,
and that file's own section header claims the normalisation matches *"the official client and
replayService"* (`:63`) when replayService in fact carries a second, weaker copy of the logic.
This is the defect class REQ-083 exists to prevent, sitting inside the requirement C2-C003 found
has no proof at all. `normaliseRgsUrl` is exported from the locked `rgsService.ts` and can be
imported rather than reimplemented, so the fix needs no lock lift. Honest caveat on reachability: I
have no evidence the platform ever emits a trailing slash, and the doc's example URL does not have
one, so this is a latent shape defect rather than an observed failure. MEDIUM.

**NEW-2. REQ-098's error surface prints an untranslated developer string, including the full RGS
URL, to the player in all sixteen locales.** `ReplayMode.svelte:100` is
`error = e?.message ?? $tr('replayLoadError')` and `:293` renders
`<div class="error-detail">{error}</div>`. The thrower supplies a message every time
(`replayService.ts:134-136`):

```ts
    throw new Error(
      `Replay fetch failed (${response.status} ${response.statusText}). URL: ${url}`,
    )
```

so the `??` fallback can only fire for a thrown value with no `message`, which means the localised
`replayLoadError` and `replayPlaybackError` keys are effectively unreachable and the player always
sees the English developer text plus the endpoint URL. The `.error-title` above it IS localised via
`$tr('replayFailed')`, so the surface renders a translated heading over an untranslated body. The
sibling at `:249` has the same shape for playback failures. This is on a mandatory approval surface,
it is exactly the *"nothing player-visible may read as machine-generated"* class the standing
mandate names, and it is what REQ-098's *"appropriate message"* is not. I would tier it HIGH and it
should be fixed in the same pass that gives REQ-098 its missing proof, because a failing-fetch pass
is what would have shown it. I found no existing row for it: the finding's own grep list covered
`replayFailed`/`replayLoadError` and reported the locale definitions and the component, so the row
walked past this while looking for a gate.

**NEW-3. Two gates this batch relies on being real are wired into no workflow.**
`build_diet_verify.mjs` is named in `checks.yml` only inside a comment (`:473`, *"build_diet_verify.mjs
sat broken for ten days while its committed result..."*) and appears in neither of the other two
workflow files; `audio_verify.mjs` likewise appears in none. This matters to C001 and C005 in the
direction of making them worse, not better: C001 calls the asset gate partial because a runtime half

covered only statically. LOW as a defect, MEDIUM as a gate-inventory correction, and it is the
fourth instance in this repository of a script being cited as a gate while running nowhere.
