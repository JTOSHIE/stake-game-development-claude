## PER CLUSTER REASONING

**S2-C001 (REQ-053, no broken or missing textures, sprites, fonts or animation states).**
Two halves and they do not stand or fall together. The gate half is TRUE and I would state it
harder than the finding does: `asset_reference_gate.mjs` resolves theme-derived and literal
`assets/...` strings and asserts `existsSync(join(DIST, p))` (line 149), nothing more, and its
own header says the runtime-request half belongs to `build_diet_verify.mjs`. So the whole
missing-ASSET class is covered twice and the "broken ... animations" clause of the source line
(`approval_guidelines_front_end_communication.md:23`, "Ensure the game is free of visual bugs,
including broken or missing assets or animations") is covered nowhere. The gate is CI wired at
`checks.yml:492,496` with a `--self-test` leg, so convention (p) is satisfied for what it does
cover. The INSTANCE half is where the finding fails. I derived the cited geometry rather than
trusting it: `GameGrid.svelte:62-74` gives `CELL_H 100`, `GAP 4`, `TILE 104`, `STRIP 7`,
`CANVAS_H 412`, so the strip is 724px tall; at `DROP_H = 520` (line 499) the strip starts 520px
above rest and exactly one tile row occupies the top 100px of the 412px window, leaving 312px
bare, which reproduces the Session 1 figure to the pixel. It is reachable: `reelMode.ts:39`
returns `'drop'` by default. But `reelMode.ts:4-6` documents that choreography as "releases the
same tiles from above the frame with gravity easing", so the bare window is the intended
drop-in, decaying to zero over `FALL` 400ms (260 turbo) per reel. Calling it a broken animation
state is an art ruling, not a mechanical fact, and the finding presents it as the latter. Real
defect (REQ-053's animation clause has no proof path at all), stated cause not sound.

**S2-C002 (REQ-079, replay loads with no session).** The observation that no CI gate and no unit
test covers it is TRUE: `grep -rln "replay=true" frontend/scripts/` returns exactly one file,
`replay_blocker_proof.mjs`, and `.github/workflows/checks.yml` contains the string "replay" at
only four lines (412, 415, 420, 422), all of them the `replay rounds` tsx test. So per the
preamble's own rule the harness cannot refute a no-proof finding. What makes the finding
INCOMPLETE rather than CONFIRMED is the EVIDENCE class, which the register's taxonomy accepts
and the finding never searched: `reports/screens/replay-blocker/` holds six committed PNGs from
a run of that harness at the sessionless `LIVE_QS` shape, including `02_base_ready_eur.png`, and
the requirement is additionally structural rather than incidental, because `App.svelte:1169-1170`
returns from `onMount` before the token is even read at line 1180. The honest disposition is
EVIDENCED, NOT GATED, not NO_PROOF, and the tier should follow: nothing here is a player-visible
defect today, only an unprotected regression surface.

**S2-C003 (REQ-083, the GET path shape).** The assertion-level claim is TRUE and I confirmed both
legs of the search: nothing imports `fetchReplay` outside `ReplayMode.svelte:5,94`, and
`bet/replay` appears in only three places in the tree (the doc comment and template at
`replayService.ts:8,125`, and the harness wildcard at line 82). The wildcard reasoning is right
about segment ORDER and overstated as an absolute: a wrong PREFIX would escape the route, hit
the network, throw, and leave `.start-replay` never visible, so the harness does weakly pin
`/bet/replay/`. It cannot see a reordered `{game}/{version}/{mode}/{event}`, which is the shape
the requirement actually specifies. Against that, there is committed live EVIDENCE the finding
missed: I opened `reports/screens/dtt-live-2026-07-26/37_REPLAY_WORKING_event_52121_with_disclaimer.png`
and it shows the real Stake Engine bet panel (Operator stake-engine, Event ID 52121, Cost USD
1.00, Cost multiplier x1.00) beside our game rendered at the ready phase with START REPLAY,
"Mode: base", "Bet: $1.00" and the disclaimer. A wrong path shape against the live RGS returns
404 and renders the error state instead. That is a real, dated, checkable proof of the path
shape, and it is why the tier is too high. What remains true is that no assertion protects it
from regression.

**S2-C004 (REQ-085, fetch on load with no click).** Both quoted halves are accurate at HEAD

**S2-C005 (REQ-095, complete animation AND audio pipeline).** Everything quoted is true. I
verified the register row against the source rather than assuming it, because it is the kind of
row that overstates: doc line 108 does read "Play the round as normal — Show all animations,
sounds, and visual effects" and line 133 "Play full animation — Show all animations, sounds, and
results", so the audio clause is the platform's, not ours. `App.svelte:1170` `if (isReplay) return`
does precede `playBGM()` at 1212 and the `warmUpAudio()` first-gesture wiring at about 1233-1245,
and `playWin` exists at only 733, 1476 and 1497, all live. `ReplayMode.svelte` imports no
`soundService` symbol. It is INCOMPLETE in both directions, which is why the tier is right but the
picture is not. Understated: `GameGrid.svelte` DOES import `playSpinStart`, `playReelStop`,
`playAnticipation` and `playScatterLand` (line 39) and fires them from `animateSpin` (935) and
reel settle (444-445), and `soundService` gates them on nothing but `muted`, so an ordinary-round
replay is not silent, it is missing BGM and the win sound. Overstated in the other direction: see
new finding 2, a feature-triggered replay has NO audio at all, which is the worse instance of the
class the finding named and it is not in the finding.

**S2-C006 (REQ-096, present bet cost, payout and win amount).** Mechanically confirmed. The only

the `{:else if phase === 'complete'}` branch at 330-333 renders only the REPLAY AGAIN button; the

Keep/Show column says "Replay bet amount", which the ready screen and every post-`playAgain`
return satisfies. A reviewer working the checklist can tick all three from the replay experience.
So this is a real gap against the strictest reading, one line of markup to close by hoisting the
bet line out of the ready branch, and it should not be ordered ahead of anything a player would
call broken. LOW.

## NEW FINDINGS FOUND WHILE VERIFYING

**1. Not one of the thirty `*_proof.mjs` scripts is wired into CI, so no proof script's convention
(p) seeded pass can ever run on the runner.** I tested every one by name against
`.github/workflows/checks.yml`: 30 files, 30 ABSENT, zero WIRED. This is the structural cause of
four of my seven findings and it is not in `KNOWN_OPEN.md`. The worked case is the mandatory
replay surface: `frontend/scripts/replay_blocker_proof.mjs:17-22` carries a real seeded pass,
"SEEDED (convention (p)): the shipped defect form is re-introduced into the served page ... The
proof must go RED here", and the CI file's only replay step is
`.github/workflows/checks.yml:420-422` "`- name: replay rounds` ... `run: npx tsx
src/lib/services/replayRounds.test.ts`". The proofs may well be intended as one-shot evidence
producers rather than gates, which is a legitimate design; the finding is that the project's own
no-proof taxonomy treats a non-wired script as no proof, and thirty scripts sit on that side of
the line while their committed frames are cited as if they were protection.

**2. A feature-triggered replay plays no audio at all, which is a worse instance of S2-C005's class
than the one it names.** `ReplayMode.svelte:156-177` handles `if (script.triggered)` entirely
through `FreeSpinsPresentation` and never calls `gridRef.animateSpin`, so none of GameGrid's four

`translations`, `themeStore`, `roundInterpreter`, `scatterEscalation`, `speedMode` and
`presentationCheckpoint`, and `MaxWinCelebration.svelte:10-14` imports `svelte`, `socialMode`,
`gameStore`, `translations` and `modalGuard`. No `soundService` in either. So the round type the
platform is most likely to ask for an event id for, per doc line "provide event IDs for different
scenarios for every bet mode", is the one that replays in silence against a requirement whose own
words are "Show all animations, sounds, and visual effects".
