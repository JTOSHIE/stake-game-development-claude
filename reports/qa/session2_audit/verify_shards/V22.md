## PER CLUSTER REASONING

**S2-C075.** Every mechanical part of this survives a hostile read. The validate step tests
`index.json` and nothing else; the five `books_*.jsonl.zst` are matched by `.gitignore:9`
(`**/library/**`) and are absent from `git ls-files`, so an `actions/checkout@v4` tree cannot
contain them; `index.json` names all five as each mode's `events`. I looked for a gate that
would fail and found the opposite: `checks.yml:502-509` documents the condition as already
known, "Run at HEAD with the private books absent, the verifier produced five ... and printed
PASS. The books are gitignored, so that is what EVERY [run sees]", and its CI step runs
`python3 tools/verify_books_lookup_equality.py --self-test` rather than the real bundle. So
there is no proof path that would catch a seven-file math upload. Where I part company with the
finding is tier. This is manual dispatch only, `do_upload` defaults false, and
`publish-stake-engine.yml:37` still carries `STAKE_TEAM: REPLACE_WITH_TEAM_SLUG`, so no upload
can succeed as configured without a deliberate edit; the workflow's own text also concedes the
platform checks are advisory under `--yes`. Nothing here is player-visible or submission-
blocking today. It is a live trap on the publish path that will be armed the moment someone
fills in the team slug, which is MEDIUM, not HIGH.

**S2-C076.** The licence facts are true: the only root licence file is `LICENSE`, MIT,
`Copyright (c) 2025 Stake Engine`, unmodified, and `WRS_MASTER_DOCUMENT.md:28` is indeed a
tool-licence archive row (Stability AI, audio provenance) that says nothing about the
repository's own outbound grant. Two parts of the finding do not stand. First, the juxtaposition
against CLAUDE.md's "No Stake branding in shipped assets or text" is a category error: `LICENSE`
does not ship. `frontend/dist/` at HEAD contains `assets`, `build-info.json`, `favicon-32.png`
and `index.html` only, and `dist_hygiene_2026-07-26.json` records a seeded case "a bare LICENSE
with no extension" with `"caught": true`, so that class is gate-held. Second, and this is the
substantive correction, **"No root document addresses it" is false**. `README.md:97` opens a
section headed "## Licence and IP" and `:102-103` says "The repository carries no open-source
licence grant: it is published for platform review and audit, not for reuse." A root document
addresses it squarely, and asserts the opposite of what the tree contains: a tracked MIT grant
permitting anyone "to use, copy, modify, merge, publish, distribute, sublicense, and/or sell".
So the real cause is not silence, it is a root README making a licensing claim its own
repository contradicts, which is a worse finding than the one raised and the one an external
reviewer would hit first, because the README is the front door. HIGH stands on that basis, and
(l.8) escalation stands: this is an owner and Fable question, not a builder edit.
