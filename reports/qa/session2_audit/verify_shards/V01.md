## PER CLUSTER REASONING

**S2-C001, CONFIRMED_WRONG_CAUSE.** Three separate things are true and the finding fuses them
badly. (1) The wiring quote is exact and the gate is a real gate, not a script that prints
PASS: `- name: asset references, seeded-violation self-test` sits immediately above it at
checks.yml:490-492, so convention (p) is satisfied within the gate's own scope. (2) The gate's
scope really is narrower than REQ-053. Its own header states what it reads: "Every literal
`assets/...` string in the source tree" and the `themeStore.ts` derivations, "Both are then
required to exist in `dist/`" (frontend/scripts/asset_reference_gate.mjs:26-30). REQ-053 says
"No broken or missing textures, sprites, fonts or animation states in any reachable game
state". A static reference-to-existence check cannot see a file that exists and is corrupt, it
cannot see an animation state, it does nothing about reachability, and fonts are self-hosted
through `@fontsource` rather than through an `assets/...` literal, so the requirement's own word
"fonts" is outside the scan entirely. The gate's header hands the runtime half to
`build_diet_verify.mjs`, and that script appears in NO step of checks.yml (I listed all 40
static steps and all 10 browser legs), so the half it names as covered elsewhere is not covered
in CI at all. (3) None of that supports a NOT_MET. The cited line is `const DROP_H = 520`, a
drop-animation constant, and the finding demonstrates no broken and no missing asset anywhere.
The real position is a PARTIAL PROOF on a player-visible requirement, which under the standing
mandate still has to be closed, but grading it NOT_MET misdirects the fix order towards hunting
a defect nobody has seen. **Real cause of the recorded gap: the gate covers reference-to-
existence only, and the runtime-request half it defers to is unwired.** Why the path citation
points at GameGrid.svelte:499 I cannot tell, and I will not invent a reason.

## NEW FINDINGS FOUND WHILE VERIFYING

**NEW-V01-1: the localised replay error string is unreachable, so every locale shows an
English technical string with an internal URL in it.** `frontend/src/lib/components/ReplayMode.svelte:100`
reads `error = e?.message ?? $tr('replayLoadError')`, and `:293` renders it as
`<div class="error-detail">{error}</div>`. The thrower ALWAYS supplies a message:
`` throw new Error(`Replay fetch failed (${response.status} ${response.statusText}). URL: ${url}`,) ``
(`frontend/src/lib/services/replayService.ts:134-136`), and a network failure throws the
platform's own English `TypeError`. So `?? $tr('replayLoadError')` can never fire on the path it
was written for, and the sixteen locale definitions of `replayLoadError` are dead for the real
failure. What a player on a shared replay URL sees, in any of the sixteen languages, is
"Replay fetch failed (500 Internal Server Error). URL: https://rgs.stake-engine.com/bet/replay/...".
Against doc:136, "Handle errors, Show an appropriate message if replay data fails to load", a
raw status line plus an internal endpoint is not an appropriate message, and under the standing
mandate ("Nothing player-visible may read as machine-generated") it is a machine-tell on a
mandatory approval surface. Same class as S2-C007 and four lines from it. The localised title
above it (`{$tr('replayFailed')}`, :292) is correct, which is what makes the untranslated detail
line read as an oversight rather than a decision.

**NEW-V01-2: a 200 response with an unusable `state` produces a silent empty replay, not the
error state.** `ReplayMode.svelte:141-143` is
`const events: RawEvent[] = Array.isArray(response.state?.events) ? (response.state.events as RawEvent[]) : []`,
a silent fallback, and the interpreter substitutes an empty base spin rather than refusing:
`baseSpin ?? newSpin('base', null, [], 1)` (`frontend/src/lib/services/roundInterpreter.ts:251`).
Trace it: `board` becomes `[]`, so `if (gridRef && board.length > 0)` at :213 skips the
animation entirely, `boardSymbols.set([])`, then after the two second wait `phase = 'complete'`.
No throw, so the catch at :247 never runs and `phase = 'error'` is never reached. The player gets
a static grid, a printed win amount and PLAY AGAIN, which is precisely the "blank screen"
outcome REQ-098 exists to prevent, and precisely the empty-static-grid failure that R2R JOB 5
was raised to fix (recorded in this file's own comment at :120-133). There is no guard anywhere
between "fetch succeeded" and "round is presentable". Honest caveat on reachability: our own
maths does emit `state.events`, so this needs an RGS returning 200 with an empty or
differently-shaped state, which I cannot prove happens. It is a missing validation of an
external payload on a mandatory surface, not an observed frame.
