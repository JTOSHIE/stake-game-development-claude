## NEW FINDINGS FOUND WHILE VERIFYING

**N1. CI gate 13 cannot exercise an ordinary WIN or BIG WIN round in `bonus` or `super`, and
the reason is a shadowing bug in the fixture categoriser, not an absence of such rounds.**
This is the same class as C032 and sits a few lines away from it.

`frontend/scripts/extract_replay_fixtures.mjs:40-48`:

```
function categorise(round) {
  const pm = round.payoutMultiplier
  const triggered = round.events.some((e) => e.type === 'freeSpinTrigger')
  if (pm >= CENTIBET_CAP) return 'cap'
  if (triggered) return 'feature'
  if (pm === 0) return 'loss'
  if (pm >= BIG_WIN_CENTIBETS) return 'bigWin'
  return 'win'
}
```

The categoriser is first-match exclusive and `triggered` is tested before `bigWin` and `win`.
Every `bonus` and `super` round is a triggered round by construction (the buy guarantees a
3-plus trigger), so those two modes can only ever yield `cap` or `feature`, which is exactly
the fixture set on disk. The consequence is that the gate whose stated purpose is the
round-two BLOCKER "an ordinary round replayed as an empty, static grid"
(`replayRounds.test.ts:4-8`) never runs an ordinary bonus or super win through
`interpretEvents`, although both categories demonstrably exist in those modes:
`REPLAY_TEST_EVENTS.md:26-27` gives bonus normal win `130` and big win `0`, super normal win
`1484` and big win `0`. Nothing in the extractor, the test or `REPLAY_TEST_EVENTS.md` states
this omission or gives it a reason, unlike the Loss row, which does carry one at `:30`. Fix
shape: order `triggered` after the payout bands, or emit both a category and a
triggered flag so a triggered big win can populate `bigWin` as well as `feature`. Suggested
tier MEDIUM (silent coverage hole in an existing gate, in the mode pair a reviewer replays
first because the buy is the headline).
