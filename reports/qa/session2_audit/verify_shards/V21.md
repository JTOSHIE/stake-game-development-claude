**S2-C068, CONFIRMED_WRONG_CAUSE. Severity LOW, not HIGH.**
The observation is exactly true: `SOURCE` is a Downloads path and the script `process.exit(2)`s
on any other machine. But the stated cause fails on both legs.

Leg one, CLAUDE.md point 4. It requires "Source path, source hash, shipped hash, dimensions,
what the supplier claimed and what the measurement found" be RECORDED. It is:
`GENERATION_NOTE_composed_master.md:9-11` records the found-at path, the source SHA-256 and the
source byte count. Point 4 nowhere requires the source to be reachable or committed, and
CLAUDE.md names this exact note as "the shape" a provenance record should take. The finding
reads a recording requirement as a reachability requirement.

Leg two, convention (m). It governs "External documents ... before work cites them", and its
worked example is the three unsupplied external REVIEW documents. It exists to stop findings
being reconstructed from missing inputs. It is not an asset-reproducibility rule, and CLAUDE.md
in the same breath permits "owner-commissioned NEW DESIGNS ... for SCENE and MARKETING art,
with recorded provenance", stating the tile's origin as "Externally generated, commissioned by
the owner". So the tile is the sanctioned case, not the prohibited one.

What survives is thinner and real: a committed script whose only input lives on one machine,
with no header line saying so, will hard-fail for the next reader who tries to run it. That is
LOW hygiene, not a HIGH provenance breach. This finding also names one instance of a two-file
class, see NEW FINDINGS item 2.
